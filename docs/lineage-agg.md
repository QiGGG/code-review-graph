# 函数血缘聚合分析（lineage-agg）快速上手

`lineage-agg` 在单函数血缘（`lineage`）的基础上扩展，用于回答：

**指定一个文件、或一个文件夹，其下所有函数各自的完整血缘，去重后一共覆盖了多少代码？**（总函数数 / 总代码行数 / 涉及文件数）

典型场景：改动前评估"这一个模块/一个文件牵连的全部实现有多少"，比逐个函数跑 `lineage` 再人工去重快得多。

---

## 与 `lineage` 的关系

| | `lineage` | `lineage-agg` |
|---|---|---|
| 入参 | `--function` 一个函数 | `--scope` 一个文件或文件夹 |
| 根集合 | 1 个函数 | 作用域内**所有**函数类节点 |
| 血缘展开 | 单个根双向展开 | 每个根各自双向展开 |
| 去重 | 单个血缘内天然无重复 | **跨根去重**：同一函数被多个根的血缘覆盖只计 1 次 |
| 输出 | 血缘树 + 规模统计 | 聚合规模统计 + 文件级明细 |

两个命令共享同一套统计口径（按函数身份去重、函数行数求和），结果可在同一计量单位下相互比较。

---

## 安装与前置条件

与 `lineage` 完全相同：

- 从本地源码安装（`uv tool install . --no-cache` 等，见 `docs/lineage.md` 安装一节）；
- 血缘数据来自知识图谱，先执行 `code-review-graph build`（首次）或 `update`（增量）；
- 图谱文件枚举基于 `git ls-files`，**新建源文件需先 `git add -N <文件>`** 再 `update`。

```bash
# 分析单个文件下所有函数

# 分析某个文件夹（递归含整棵子树）
```

## 参数说明

| 参数 | 必填 | 说明 |
|---|---|---|
| `--scope <路径>` | ✅ | 作用域路径：单文件或文件夹（判定规则见下），也接受从仓库根目录开始的相对路径或绝对路径 |
| `--exclude-tests` | 否 | 排除测试函数/文件（默认**计入** Test 节点，口径与 `lineage` 一致） |
| `--json` | 否 | 输出结构化 JSON |
| `--repo` | 否 | 指定仓库根目录（默认自动探测） |

### `--scope` 判定规则

1. 归一化路径分隔符（`/`、`\` 均可）。
2. 若该路径在磁盘上**存在且是目录** → 文件夹模式，递归含整棵子树。
3. 若**存在且是文件** → 单文件模式。
4. 若磁盘上不存在 → 按"路径片段连续包含"在 `git ls-files` 文件清单中匹配：唯一命中即用之；多义或无命中时报错并列出候选，绝不盲选。

> 注意：文件夹模式下文件枚举基于 `git ls-files`，未被 git 跟踪的文件不会入统计。

### 常用组合

```bash
# 文件作用域，排除测试
code-review-graph lineage-agg --scope code_review_graph/tools/query.py --exclude-tests

# 导出 JSON 供其他工具加工
code-review-graph lineage-agg --scope src/order --json > agg.json

# 从 IDE 复制的绝对路径直接使用
code-review-graph lineage-agg --scope "D:\repo\src\order"
```

## 统计口径（重要）

- **去重身份**：函数身份 = 图节点键 `qualified_name`（`文件路径::[类名.]函数名`）。同一函数无论被多少个根函数、多少条血缘路径到达，只计 1 次行数。因身份键内嵌文件路径，**不同文件中的同名函数各自独立、互不混淆**。
- **行数口径**：每个纳入函数按 `行尾 - 行首 + 1` 求和（与 `lineage` 单函数一致）；**不做物理行并集去重**（同一行被外层函数与嵌套 def 同时覆盖时按各自函数行数计入）。理由见 `docs/adr/0001`。
- **纳入种类**：Function 与 Test 节点；类方法即带 `parent_name` 的 Function/Test，Class 节点本身不计行数。
- **覆盖可越界**：血缘覆盖不受作用域限制，可延伸至全仓任意文件；作用域只决定"哪些函数入根"。标记为 `(外部/未解析)` 的节点（如第三方库函数）不计入行数。
- **嵌套函数**：函数体内的嵌套 def 同样入根并参与统计；其既有"同文件同名嵌套 def 合并"局限为建图层已知边界（见"已知局限"）。

### 为什么"总行数"不等于"作用域文件行数相加"？

两个原因，方向相反：根函数自己的血缘会牵连作用域**外**的文件（越界覆盖，使总数变大）；多个根共享同一下层函数时只计一次（去重，使总数变小）。所以聚合结果需要自己运行获得，不能由作用域内函数行数简单推算。

## 输出结构说明

### 文本输出（默认）

- 作用域描述 + 模式（文件/文件夹）
- 汇总：根函数数、去重后函数总数、总行数、涉及文件数、外部未解析引用数
- 文件级明细：按行数降序列出每个文件的行数与函数数

### JSON 字段（`--json`）

| 字段 | 含义 |
|---|---|
| `status` | `ok` / `ambiguous` / `error` |
| `scope` | 本次查询的作用域路径 |
| `scope_type` | `file` / `dir` |
| `function_count` | 去重后覆盖的函数总数 |
| `total_loc` | 去重后覆盖的总代码行数 |
| `file_count` | 涉及文件数 |
| `external_references` | 外部未解析引用数 |
| `files[]` | 文件级明细（`file_path` / `functions` / `loc`，按 `loc` 降序） |
| `roots[]` | 每个根函数的身份清单（`qualified_name` / `name` / `file_path` / 行数），供程序化下钻（配合 `lineage --function` 查看某个根的血缘树） |
| `exclude_tests` | 本次是否排除了测试 |

## 常见问题

**Q: 报错 `at least one of --scope is required`？**
- `--scope` 是唯一必填参数，未提供时命令报错退出。

**Q: 提示 scope 匹配多义 / 找不到？**
- 作用域路径在磁盘上不存在且片段匹配到多个候选时返回候选列表；无命中则报错。写从仓库根目录开始的相对路径最稳妥。

**Q: 统计结果比我预想的大？**
- 正常。血缘会越界覆盖作用域外的文件（函数调用了别的模块的工具函数等），这是"覆盖"而非"本文件夹行数"。

**Q: 为什么用了 `--exclude-tests` 数字还是含测试？**
- 排除规则按解析器的 Test 判定（文件名 `test_*`/`_test.py`、`test_` 前缀函数、JS/TS `describe/it/test` 等）。若某些测试未被识别为 Test 节点，仍会以 Function 身份计入；这是解析层的既有判定边界。

**Q: 没建图 / 新文件未入图导致漏计？**
- 先 `code-review-graph build` / `update`；新建文件先 `git add -N <文件>` 再 `update`。

## 已知局限与后续方向

- **嵌套函数身份局限（已记录）**：非 Julia/C++ 语言函数体内的嵌套 def，身份键不含外层函数名，同文件同名嵌套 def 会在建图时合并为单节点。聚合功能沿用此现状，不做二次处理；根治需改建图 schema 并全仓重图，列为独立事项。
- **不做物理行并集口径（ADR-0001）**：有意与单函数口径保持一致，非疏漏。
- **HTML 交互式查询（未实施）**：已评估在浏览器界面内做任意函数/作用域查找的方案，本轮**不实施**，保留为后续方向。
